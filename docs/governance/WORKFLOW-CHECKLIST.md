# Workflow Checklist

> **이 문서는 핵심 관문입니다.** Claude에 프롬프트를 넘기기 전에 Gen님이 반드시 거쳐야 하는 단계들입니다.
> 각 작업(Day)의 시작, 실행, 마무리 단계를 체크리스트로 관리합니다.

---

## Phase 1: 시작 전 (Before)

Gen님이 직접 수행하는 단계입니다. Claude에게 넘기기 전에 이 항목들을 확인하세요.

### 1-1. 부채 확인
- [ ] `docs/TECH-DEBT.md`의 OPEN 항목이 5개 미만인가?
  - 5개 이상이면 → ⛔ 새 기능 추가 금지. 부채 해소부터.
  - 현재 OPEN: ___ 개

### 1-2. 작업 정의
- [ ] 이번 작업에서 **무엇을 달성할 것인가?** (한 문장으로)
  - 예: "flickering 5개 중 TD#1 useIsMobile 해결"
  - 작성: _______________________________________________
- [ ] **성공 기준(Success Criteria)**: 어떻게 되면 "완료"인가?
  - 예: "모바일에서 /korea/visa/d-10 새로고침 시 레이아웃 깜빡임 없음"
  - 작성: _______________________________________________
- [ ] **롤백 기준**: 어떤 상황이면 전부 되돌리는가?
  - 예: "빌드 실패, 또는 다른 페이지에서 새로운 flickering 발생"
  - 작성: _______________________________________________

### 1-3. Step 0 리뷰 (아키텍처/리스크 사전 점검)
- [ ] `docs/governance/ARCHITECTURE-MAP.md`에서 이번 작업이 영향 미치는 영역을 확인했는가?
  - 영향 범위: _______________________________________________
  - 위험도 (Section 8 참조): 🔴 최고 / 🟡 중간 / 🟢 낮음
- [ ] `docs/governance/DECISION-LOG.md`에서 관련 이전 결정을 확인했는가?
  - 관련 결정: _______________________________________________
- [ ] **PII 체크**: 이 기능이 개인정보를 다루는가? → `PII-DATA-FLOW.md` 참조
  - Y / N — Y이면 PII 흐름도에 새 경로 추가 필요
- [ ] **법률 체크**: 법률 위반 리스크가 있는가? → CLAUDE.md Legal Bright Lines 참조
  - Y / N — Y이면 법률 감사 필수

### 1-4. One-Pager (기능 추가 시에만)
> 새 기능 추가 작업일 때만 작성. 버그 수정/부채 정리 시에는 건너뛰기.

- [ ] **What**: (한 문장) _______________________________________________
- [ ] **Why**: (왜 필요한지) _______________________________________________
- [ ] **성공 기준**: (Phase 1-2에서 정의한 것과 동일)
- [ ] **안 하는 것**: (범위 제한) _______________________________________________

## Phase 2: Claude에게 요청 (Prompt)

Claude에게 요청할 때 포함해야 하는 것들입니다.

### 2-1. Claude에게 요구할 것
- [ ] **Impact Map 요구**: "이 변경이 영향 미치는 파일 목록과 연결 관계를 먼저 보여줘"
- [ ] **선택지 요구**: "방법 2-3개를 장단점과 함께 보여줘. 추천하지 마."
- [ ] **실행 흐름 설명 요구**: "이 기능의 런타임 흐름을 5단계 이내로 설명해줘"

### 2-2. Gen님이 판단할 것
- [ ] Claude가 제시한 선택지 중 하나를 선택했는가?
  - 선택한 방법: _______________________________________________
  - 선택 이유: _______________________________________________
- [ ] "왜 이 방법이어야 하는가?" 질문을 했는가?
  - Claude의 답변이 납득 가능한가? Y / N

### 2-3. 실행 전 최종 확인
- [ ] Claude가 수정할 파일 목록을 보여줬는가?
  - 파일 수: ___ 개
  - 예상과 맞는가? Y / N
- [ ] 실행 프롬프트(있는 경우) 내용을 검토했는가?

## Phase 3: 실행 중 (During)

Claude가 작업하는 동안 확인할 것들입니다.

### 3-1. 변경 추적
- [ ] `git diff --stat` 결과를 확인했는가?
  - 변경된 파일 수: ___ 개
  - Phase 2에서 예고한 파일 수와 일치하는가? Y / N
  - 예상 밖의 파일이 변경됐으면 → Claude에게 이유 질문

### 3-2. 금지 사항 확인
- [ ] `suppressHydrationWarning` 추가 없음
- [ ] `eslint-disable` 추가 없음
- [ ] `@ts-ignore` 추가 없음
  - 위 항목이 추가됐으면 → Gen님의 명시적 승인 필요 + TECH-DEBT.md에 기록

## Phase 4: 실행 후 (After)

### 4-1. Gen님이 직접 검증
- [ ] Claude가 "여기를 확인하세요"라고 알려준 곳을 직접 브라우저에서 확인했는가?

### 4-2. 빌드 확인
- [ ] `npm run build` 성공했는가? Y / N

### 4-4. 학습 기록

- [ ] 다음에 비슷한 작업이 오면 어떻게 판단할 것인가?

## Phase 6: 주간 리뷰 (Weekly Review)

매주 1회:

- [ ] TECH-DEBT.md: OPEN 항목 리뷰 → 우선순위 재조정
- [ ] DECISION-LOG.md: 이번 주 결정 패턴 리뷰 → "같은 실수 반복하고 있나?"
- [ ] ARCHITECTURE-MAP.md: 이번 주 변경 사항 반영 → "시스템 흐름을 설명할 수 있나?"
- [ ] Architecture Walkthrough: 아무 페이지 하나 골라서 데이터 흐름을 말로 설명해보기
  - 선택한 페이지: _______________________________________________
  - 설명 가능했는가? Y / N / 부분적

---

*이 체크리스트는 작업 규모에 따라 축소 적용 가능합니다:*
- **간단한 수정** (버그 픽스, 텍스트 변경): Phase 1-2 간소화, Phase 4 필수
- **중간 작업** (컴포넌트 수정, 데이터 변경): 전체 적용
- **대규모 작업** (새 기능, 아키텍처 변경): 전체 적용 + Architecture Map 업데이트 필수
