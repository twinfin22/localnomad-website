## 4. 기능 목록

### 4-1. 비자 체크리스트 / 상세 페이지

비자별로 한 페이지에 모든 정보를 3-layer 구조로 제공.

**Glanceable Zone (상단)**:
- 자격 요건 at a glance (표 형식)
- 색상 코딩 (빨강/노랑/초록)

**Action Zone (중단)**:
- 신청 절차 (7+ 스텝)
- 필요 서류 체크리스트
- 수수료·처리기간

**Context Zone (하단)**:
- FAQ (10+개)
- 공식 출처 링크
- 커뮤니티 팁 (Reddit, FB, Discord에서 수집한 가산점 팁)

### 4-2. Visa Type Overview

비자 종류를 한눈에 보여주는 페이지. Type A부터 F까지, H 포함. 카테고리별 분류 + 간단한 설명.

### 4-3. Visa Comparison Tool

비자 2-4개를 나란히 비교. 자격, 기간, 서류, 비용 등 표 형식.

### 4-4. Visa Path Simulator

A 비자 → B 비자 전환 시 필요한 것. 전환 경로·요건·타임라인·서류 시각화. Renewal/Extension 포함.

**데이터 출처**: HiKorea Visa Navigator PDF에 비자 전환 플로우차트 포함 → 이를 기반으로 구조화

### 4-5. 비자 대시보드 (로그인 필요)

**Glanceable Zone**:
- Visa Health Monitor (현재 비자 상태 요약)
- D-Day 카운트다운 (비자 만료일, 연장 신청 가능일, 세법상 거주자 183일 도달 시점)
- Next Action CTA ("지금 FBI 범죄경력증명서를 신청해야 3주 뒤 비자 신청 가능")
- Progress bar

**Action Zone**:
- 상세 체크리스트 (서류 준비 진행도)
- Upcoming deadlines
- Alerts & notifications

**Context Zone**:
- 서류 가이드
- Visa Path Simulator 연결
- Related News (비자 정책 트렌드)
- Community Q&A (디스코드 연결 — 추후)

**타임라인 알림 로직**:
- 공공 데이터: 서류별 발급 소요기간, 유효기간 → 시스템이 보유
- 사용자 입력: 비자 만료일, 신청 예정일 등 개인 날짜
- 시스템이 역산하여 "언제까지 뭘 해야 하는지" 타임라인 생성

**알림 방식**: 대시보드 내 시각적 표시 (MVP) → 이메일 알림은 post-MVP에서 추가

**OASIS 점수 트래커**: 점수제 비자(D-8-4 등)의 점수 시뮬레이션/트래킹

**Tax Residency Tracker**: 183일 거주자 판정 카운터

### 4-6. Tax 페이지 (Coming Soon)

한국 페이지에서 Tax 섹션은 "Coming Soon" + 이메일 수집 ("Be the first to know")

### 4-7. File Sanitizer (추후 추가)

서류 리사이징, 제목 템플릿 준수 체크 등. 클라이언트 사이드 전용 (개인정보 파일이 서버로 전송되지 않아야 함). MVP 이후 추가.

### 4-8. Related News (추후 추가)

비자 정책 변경 뉴스를 자동 수집하여 대시보드 Context Zone에 표시.

**구현 방식**:
- 매일 1회 크론잡으로 "korea visa" 관련 뉴스 크롤링
- 법규 변경 감지 시 → 관련 비자 JSON 데이터 자동 업데이트 트리거
- 뉴스 피드는 대시보드 하단 Context Zone에 표시

**콘텐츠 업데이트 전략**:
- Visa Navigator PDF 기반 JSON은 초기 1회 구조화
- 이후 변경사항은 뉴스 크롤링 + 수동 확인 병행
- 자동 업데이트는 수수료, 처리기간 등 단순 수치 변경에 한정
- 자격 요건 변경 등 중대 변경은 수동 검증 후 반영

## 7. 디자인 원칙

1. **Mobile First**: 모바일이 기본. 데스크톱은 모바일 경험의 확장. 반응형(reactive), 직관적(intuitive) UX가 이 제품의 핵심 가치. 다른 것을 희생하더라도 모바일 UX를 우선한다 (trade-off 발생 시 Gen 확인)
2. **Info overwhelm 금지**: Frontloading 하지 않는다. Backloading — 필요할 때 펼쳐보기
3. **Peace of mind**: 사용자가 "내가 놓치고 있는 게 없다"고 느끼게
4. **3-Layer 정보 구조** (Boundless/Alma 벤치마킹):
   - Glanceable Zone: 현재 상태 요약 + 색상 코딩
   - Action Zone: 체크리스트 + 다음 행동
   - Context Zone: 상세 가이드 + 커뮤니티
5. **Backloading 원칙**: 정보는 계층적으로 숨겨놓고, 사용자가 클릭하면 펼쳐지는 방식

### Mobile First 구체 원칙

- 터치 타겟 최소 44px, 간격 8px 이상
- 한 화면에 하나의 액션 (스크롤보다 단계별 진행)
- 비자 상세 페이지: 아코디언/탭으로 정보 계층화 (모바일에서 긴 스크롤 방지)
- 대시보드: 카드 기반 UI, 스와이프 가능한 섹션
- Comparison Tool: 모바일에서는 2개씩 비교 (데스크톱은 4개)
- 폰트 최소 16px (모바일 입력 필드 줌 방지)
- 오프라인 대응: 비자 상세 정보는 정적 데이터이므로 빠른 로딩 우선

## 11. 데이터 구조

### 비자 정보 (정적 — JSON 파일)

모든 사용자에게 동일한 데이터. 빌드 시 HTML에 포함.

**Single Source of Truth (한국)**: `docs/human/VISA NAVIGATOR(Customized Stay Guide)(Eng).pdf`
- HiKorea 공식 자료 (Visa Navigator / Customized Stay Guide)
- 비자별 자격 요건, 신청 절차, 필요 서류, 전환 경로 등 포함
- 이 PDF를 기반으로 JSON 데이터를 구조화

**대만 데이터 출처**: NIA, BOCA, MOL 공식 사이트에서 수집

```
data/visas/{country}/{locale}/{visa-type}.json

예: data/visas/korea/en/f-1-d.json
    data/visas/korea/ja/f-1-d.json
    data/visas/taiwan/en/dnv.json
```

내용: 자격 요건, 신청 절차, 필요 서류, 수수료, 처리기간, FAQ, 출처 링크, 서류 소요기간(타임라인 알림용)

### 사용자 데이터 (동적 — Supabase DB)

사용자마다 다른 데이터. 로그인 필요.

- 현재 비자 종류 + 만료일
- 체크리스트 진행 상황
- 알림 설정 (대시보드 표시 시점; 이메일은 post-MVP)
- OASIS 점수 트래킹 데이터
- Tax residency 입국/출국 날짜

### 데이터 분리 원칙

```
서버에 저장 OK:     이메일, 비자 종류, 만료일, 체크리스트 진행도
서버에 저장 금지:   여권번호, ARC 번호, 신청서 ID (특히 대만)
클라이언트 전용:    File Sanitizer 처리 파일, 대만 퀴즈 데이터
```

## 14. MVP 빌드 순서 (옵션 C: 하이브리드)

### Phase 1: 골격 + F-1-D 풀스택

F-1-D 비자 하나로 전체 아키텍처를 검증한다.

```
1-1. 프로젝트 셋업
     ├─ Tech stack 확정 + 초기 구조
     ├─ i18n 설정 (en 우선, ja/zh-tw/vi 스켈레톤)
     ├─ 라우팅 구조 (/korea/visa/[type], /taiwan/visa/[type])
     ├─ 레이아웃 + 브랜딩 (Lora Bold 로고, 컬러 시스템)
     └─ Mobile-first 반응형 기본 틀

1-2. 비자 데이터 구조화
     ├─ Visa Navigator PDF → 전체 비자 JSON 스키마 설계
     └─ F-1-D JSON 데이터 작성 (en)

1-3. F-1-D 비자 상세 페이지
     ├─ 3-Layer 템플릿 (Glanceable → Action → Context)
     ├─ SEO 기본 (meta, Schema.org)
     └─ 모바일 UX 검증 (아코디언, 터치 타겟)

1-4. 인증 + 대시보드
     ├─ Supabase Auth (매직 링크)
     ├─ F-1-D 대시보드 (D-Day + 체크리스트 기본)
     └─ Supabase DB 스키마 설계
```

**Phase 1 완료 기준**: F-1-D 비자 정보 열람 + 회원가입 + 대시보드 기본 기능이 모바일에서 작동

### Phase 2: 콘텐츠 확장 + SEO

검증된 템플릿을 복제하고 SEO를 본격 가동한다.

```
2-1. 나머지 비자 상세 페이지
     ├─ 한국: E-7, D-8, H-1, F-2 (JSON + 상세 페이지)
     ├─ 대만: DNV, Gold Card (JSON + 상세 페이지, 영어만)
     └─ 다국어 번역 (ja, zh-tw, vi — 한국 비자만)

2-2. 탐색 도구
     ├─ Visa Type Overview
     └─ Visa Comparison Tool (모바일: 2개 비교)

2-3. SEO 강화
     ├─ sitemap.xml 자동 생성
     ├─ OG 이미지 (비자별)
     └─ 내부 링크 구조 (상세 ↔ 비교 ↔ Overview)

2-4. 대시보드 확장
     └─ 나머지 비자 대시보드 연결
```

**Phase 2 완료 기준**: 7개 비자 전체 정보 + 비교 도구 + SEO 작동 + 대시보드 전 비자 지원

### Phase 3: 고급 도구
