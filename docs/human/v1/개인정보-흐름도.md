# PII 데이터 흐름도 + 컴플라이언스 체크리스트

> **PII(Personally Identifiable Information)**: 개인을 식별할 수 있는 정보.
> 이름, 이메일, 여권번호, 외국인등록번호(ARC), 비자 상태 등.
>
> LocalNomad는 비자 **정보** 플랫폼이므로 PII를 최소한으로 다뤄야 함.
> 이 문서는 "어떤 개인정보가 어디에 저장되고, 어디를 거치는지"를 추적.

---

## 1. PII 데이터 분류

| 분류 | 데이터 | 현재 저장 위치 | 암호화 여부 |
|------|--------|---------------|------------|
| **인증** | 이메일, 비밀번호 해시 | Supabase Auth | ✅ Supabase 관리 |
| **인증** | Google OAuth 토큰 | Supabase Auth | ✅ Supabase 관리 |
| **진행상황** | 비자 체크리스트 완료 항목 | Supabase DB (로그인) / localStorage (비로그인) | ⚠️ Supabase: 전송 시 TLS / localStorage: 평문 |
| **퀴즈** | 퀴즈 응답 (대만) | 클라이언트 전용 (localStorage) | ❌ 평문, 서버 전송 없음 |
| **저장 안 함** | 여권번호, ARC, 비자 신청 ID | ❌ 절대 저장 안 함 | N/A |

## 2. 데이터 흐름도

```
사용자 브라우저
    │
    │  [1] 회원가입/로그인
    │  이메일 + 비밀번호 → HTTPS (TLS 1.3)
    │
    ▼
┌─────────────────────────────────┐
│         Supabase Auth            │
│                                  │
│  이메일 저장 ✅                   │
│  비밀번호 → bcrypt 해시 ✅        │
│  OAuth 토큰 → Supabase 관리 ✅   │
│                                  │
│  📍 위치: Supabase 클라우드       │
│  (AWS us-east-1 또는 설정에 따라)  │
└────────────────┬────────────────┘
                 │
                 │  [2] 인증된 요청
                 │  JWT 토큰 → 쿠키 (httpOnly, secure)
                 │
                 ▼
┌─────────────────────────────────┐
│         Vercel 서버               │
│                                  │
│  middleware.ts:                   │
│  JWT 검증만 수행 — PII 저장 안 함  │
│  로그에 이메일 기록 안 함          │
│                                  │
│  📍 PII 통과만 함, 저장 없음       │
└────────────────┬────────────────┘
                 │
                 │  [3] 비자 진행상황 조회/저장
                 │
                 ▼
┌─────────────────────────────────┐
│       Supabase DB                │
│                                  │
│  visa_progress 테이블:            │
│  user_id (UUID) + visa_type      │
│  + checklist_items (boolean[])   │
│                                  │
│  ⚠️ user_id는 UUID라 이메일과    │
│  직접 연결은 Auth 테이블 경유 필요  │
│                                  │
│  📍 RLS(Row Level Security) 적용  │
│  본인 데이터만 조회 가능            │
└─────────────────────────────────┘


비로그인 사용자 (PII 없음):

사용자 브라우저
    │
    │  퀴즈 응답, 체크리스트 → localStorage
    │  서버 전송 ❌
    │  여권번호/ARC 입력 필드 자체가 없음 ❌
    │
    └─ 끝 (서버에 PII 도달 안 함)
```

## 3. 컴플라이언스 체크리스트

### 한국 개인정보보호법 (PIPA)

| # | 항목 | 상태 | 비고 |
|---|------|------|------|
| 1 | 개인정보 수집 동의 | ⚠️ 확인 필요 | 회원가입 시 개인정보처리방침 동의 UI 있는지 |
| 2 | 수집 목적 외 이용 금지 | ✅ | 이메일은 인증용만, 마케팅 미사용 |
| 3 | 개인정보 파기 절차 | ⚠️ 확인 필요 | 탈퇴 시 Supabase에서 데이터 삭제되는지 |
| 4 | 개인정보처리방침 공개 | ⚠️ 확인 필요 | Privacy Policy 페이지 존재 여부 |
| 5 | 민감정보 수집 금지 | ✅ | 여권번호, ARC 등 수집 안 함 |

### 대만 개인자료보호법 (PDPA)

| # | 항목 | 상태 | 비고 |
|---|------|------|------|
| 1 | 대만 사용자 데이터 서버 위치 | ⚠️ 확인 필요 | Supabase 리전이 대만 외부면 고지 필요 |
| 2 | 클라이언트 전용 처리 | ✅ | 대만 퀴즈/체크리스트 데이터는 서버 전송 없음 |

### LocalNomad 자체 규칙 (CLAUDE.md Legal Bright Lines)

| # | 항목 | 상태 | 비고 |
|---|------|------|------|
| 1 | 여권번호 서버 저장 금지 | ✅ | 입력 필드 자체 없음 |
| 2 | ARC/외국인등록번호 저장 금지 | ✅ | 입력 필드 자체 없음 |
| 3 | HiKorea 인증정보 저장 금지 | ✅ | 연동 없음 |
| 4 | 대만 퀴즈 데이터 서버 전송 금지 | ✅ | localStorage 전용 |

## 4. 위험 구간 (주의)

```
⚠️  위험 구간 1: localStorage → Supabase 마이그레이션
    비로그인 → 로그인 시 localStorage 데이터를 Supabase로 이동
    이 과정에서 의도치 않게 대만 퀴즈 데이터가 서버로 전송되면 안 됨
    → 마이그레이션 코드에서 대만 퀴즈 데이터 필터링 확인 필요

⚠️  위험 구간 2: Supabase 로그
    Supabase 대시보드에서 쿼리 로그에 user_id가 노출될 수 있음
    → 프로덕션에서 로그 보존 기간 확인

⚠️  위험 구간 3: Vercel 로그
    Vercel Functions 로그에 요청 헤더(쿠키 포함)가 기록될 수 있음
    → Vercel 로그 설정 확인
```
