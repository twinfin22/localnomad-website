> **v1 기록**: `docs/human/v1/개인정보-흐름도.md` 참고

## 1. 데이터 분류

### 서버 저장 OK (Supabase DB)

| 데이터 | 용도 | 민감도 |
|--------|------|--------|
| 이메일 주소 | 매직 링크 인증 + 알림 (post-MVP) | 중 |
| 현재 비자 종류 | 대시보드 표시 | 낮음 |
| 비자 만료일 | D-Day 카운트다운 | 중 |
| 체크리스트 진행도 | 진행 상황 저장 | 낮음 |
| OASIS 점수 데이터 | 점수 트래킹 | 낮음 |
| Tax residency 날짜 | 183일 카운터 | 중 |

### 서버 저장 금지

| 데이터 | 이유 |
|--------|------|
| 여권번호 | 개인정보 보호 |
| ARC 번호 (외국인등록번호) | 대만 법규 (Immigration Act §56) |
| 신청서 ID | 개인정보 보호 |
| HiKorea 계정 정보 | 법적 리스크 (스크래핑 금지) |
| 비밀번호 | 매직 링크 인증 → 비밀번호 자체가 없음 |

### 클라이언트 전용 (localStorage)

| 데이터 | 이유 |
|--------|------|
| File Sanitizer 처리 파일 (post-MVP) | 서류 파일이 서버에 전송되면 안 됨 |
| 대만 퀴즈/체크리스트 입력값 | 대만 법규 컴플라이언스 |

## 2. 데이터 흐름도

```
[사용자] → 매직 링크 요청 (이메일 입력)
                │
                ▼
        [Supabase Auth]
        이메일로 매직 링크 발송
                │
                ▼
[사용자] → 매직 링크 클릭 → 세션 쿠키 발급
                │
                ▼
[사용자] → 대시보드 데이터 입력
                │
                ▼
        [Supabase DB]
        저장: 비자 종류, 만료일, 체크리스트 진행도
        저장 안 함: 여권번호, ARC 번호 (입력 필드 자체 없음)
                │
                ▼
        [Supabase RLS]
        본인 데이터만 조회 가능 (Row Level Security)


비로그인 사용자:
[사용자] → 비자 정보 열람 → 서버에 PII 전송 없음
[사용자] → File Sanitizer → 브라우저 내 처리만 → 서버 전송 없음
```

## 3. 컴플라이언스 체크리스트

### 한국 개인정보보호법 (PIPA)

| # | 항목 | 상태 | 비고 |
|---|------|------|------|
| 1 | 개인정보 수집 동의 | ⚠️ 구현 필요 | 매직 링크 가입 시 개인정보처리방침 동의 UI |
| 2 | 수집 목적 외 이용 금지 | 설계 반영 ✅ | 이메일은 인증 + 알림용만 |
| 3 | 개인정보 파기 절차 | ⚠️ 구현 필요 | 탈퇴 시 Supabase 데이터 삭제 |
| 4 | 개인정보처리방침 공개 | ⚠️ 구현 필요 | Privacy Policy 페이지 |
| 5 | 민감정보 수집 금지 | 설계 반영 ✅ | 여권번호, ARC 등 입력 필드 없음 |

### 대만 개인자료보호법 (PDPA)

| # | 항목 | 상태 | 비고 |
|---|------|------|------|
| 1 | 대만 사용자 데이터 서버 위치 | ⚠️ 확인 필요 | Supabase 리전 확인 |
| 2 | 클라이언트 전용 처리 | 설계 반영 ✅ | 대만 퀴즈/체크리스트 서버 전송 없음 |

## 4. 위험 구간 (v2에서 주의)

```

```
