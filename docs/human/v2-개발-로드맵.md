## 전체 구조 & 타임라인

```
Phase 1: 골격 + F-1-D 풀스택        ← 아키텍처 검증      3~5일
Phase 2: 콘텐츠 확장 + SEO           ← 트래픽 확보        4~6일
Phase 3: 고급 도구                    ← 유저 전환/리텐션    5~8일
Post-MVP: 이메일, 뉴스, 유료화        ← 성장              트리거 기반
                                                   총 예상: 2~3주
```

> 📘 **타임라인 전제조건**:
> - Claude Max 24시간 가동 (코딩 실행)
> - Gen님 즉시 리뷰 (의사결정 포인트에서 대기 없음)
> - 번역: AI + 역번역 QA
> - 업계 솔로 개발자 평균 12~16주 → AI 네이티브 + 즉시 리뷰로 2~3주
>
> **태스크별 예상 시간 안내**: Claude가 매 태스크 시작 시 "예상 N분/N시간, 의사결정 필요 시점: ~시"를 알려드림.
> 단순 작업 ±10분, 복잡한 작업 ±30분~1시간, 디버깅 포함 시 편차 커짐.

## 성공 지표 (KPIs)

### 트래픽 (오가닉, 광고 없음 기준)

| 시점 | 목표 범위 | 벤치마크 참고 |
|------|----------|-------------|
| 런칭 1개월 | 50~300 세션 | 런칭 버즈 + 직접 유입. SEO 아직 안 먹음 |
| 3개월 | 200~1,500 세션/월 | Google 인덱싱 시작, 롱테일 키워드 첫 랭킹 |
| 6개월 | 500~5,000 세션/월 | 콘텐츠 누적, 일부 page 1 진입 |
| 12개월 | 2,000~10,000+ 세션/월 | 콘텐츠 품질 높으면 우상향 |

### SEO

| 지표 | 벤치마크 |
|------|---------|
| Google 인덱싱 | 4일~4주 |
| 경쟁 낮은 키워드 page 1 | 3~6개월 |
| 경쟁 높은 키워드 page 1 | 6~12개월+ |
| 새 페이지 1년 내 top 10 진입률 | 1.74% (진입 시 40%가 1개월 내) |

### 전환

| 단계 | 벤치마크 |
|------|---------|
| 방문자 → 무료 가입 | 2~5% (평균), 11%+ (상위) |
| 무료 → 유료 (MAU 100 도달 후) | 8~10% |

### 참여도

| 지표 | 좋음 | 평균 | 나쁨 |
|------|------|------|------|
| 바운스율 | < 40% | 41~50% | > 70% |
| 세션 시간 | > 3분 | 2분 38초 | < 1분 |

> 📘 **MAU 100 역산**: 가입 전환율 2~5% 가정 시, 월 2,000~5,000 세션이면 MAU 100 도달 가능.

### 1-1. 프로젝트 셋업

| 태스크 | 상세 | 완료 기준 |
|--------|------|----------|
| Next.js 16 초기화 | App Router, TypeScript 5, Tailwind CSS 4 | `npm run dev` 정상 실행 |
| shadcn/ui 설치 | New York 테마, 필요 컴포넌트만 | 버튼/카드/아코디언 렌더링 확인 |

| 브랜딩 | Lora Bold 로고, `#1B4965` + `#D64045` 컬러 시스템 | 로고 + 파비콘 표시 |
| Mobile-first 기본 틀 | 반응형 레이아웃, 44px 터치 타겟, 16px 최소 폰트 | 모바일 뷰포트에서 깨지지 않음 |
| 랜딩 페이지 | 히어로 (아래 상세) + 국가 선택 CTA | localnomad.club 첫 화면 작동 |
| Analytics 설정 | Google Analytics (GA4) | 이벤트 트래킹 + MAU 대시보드 확인 가능 |
| 성능 기준선 | Core Web Vitals "좋음" 구간 목표 | Lighthouse 모바일 ≥ 90 |

**Core Web Vitals 목표 (모바일 4G 기준)**:

```
             목표 (좋음)    보통         나쁨
LCP         ≤ 2.5s       2.5~4.0s     > 4.0s    ← 가장 큰 콘텐츠 로딩 시간
CLS         ≤ 0.1        0.1~0.25     > 0.25    ← 레이아웃 밀림 정도
INP         ≤ 200ms      200~500ms    > 500ms   ← 클릭/탭 반응 속도
```

> 📘 **CWV란?** Google이 사이트 UX를 측정하는 3가지 지표. 검색 순위에 영향.
> LCP = 페이지 로딩 체감 속도, CLS = 요소가 갑자기 밀리는 현상, INP = 터치 반응 속도.
> LocalNomad는 정적 JSON + SSR이라 "좋음" 구간 달성 가능.

**의존성**: 없음 (첫 태스크)

**결정 필요**:
- [x] Analytics 도구 → Google Analytics (GA4) 확정
- [x] 랜딩 페이지 히어로 확정 (아래 참고)
- [x] Core Web Vitals → "좋음" 구간 목표 확정 (LCP ≤ 2.5s, CLS ≤ 0.1, INP ≤ 200ms)

### 1-2. 비자 데이터 구조화

### 1-3. F-1-D 비자 상세 페이지

| 태스크 | 상세 | 완료 기준 |
|--------|------|----------|
| 3-Layer 템플릿 | Glanceable → Action → Context 구조 | 서버 컴포넌트 기본, Action Zone만 Client |
| Glanceable Zone | 자격 요건 표 + 색상 코딩 | 모바일에서 한눈에 파악 가능 |
| Action Zone | 체크리스트 + 절차 스텝 | 아코디언/탭, 터치 타겟 44px |
| Context Zone | FAQ + 출처 링크 + 커뮤니티 팁 | 접힌 상태 기본, 펼쳐보기 |
| SEO 기본 | 동적 meta title/description, Schema.org (FAQ + HowTo) | Google 리치 스니펫 테스트 통과 |
| 디스클레이머 | 한국 법률 디스클레이머 하단 표시 | 스펙 Section 10 문구 그대로 |
| RSC 비율 체크 | Client Component ≤ 20% | 빌드 후 번들 분석 |

**의존성**: 1-2 완료 (F-1-D JSON 데이터 필요)

**이 단계가 핵심**: 여기서 만든 템플릿이 Phase 2에서 7개 비자에 복제됨. 모바일 UX + RSC 규율이 이 단계에서 완벽해야 함

### 1-4. 인증 + 대시보드

| 태스크 | 상세 | 완료 기준 |
|--------|------|----------|
| Supabase 프로젝트 설정 | Auth + DB + RLS 정책 | 매직 링크 이메일 수신 |
| 매직 링크 인증 | 회원가입 + 로그인 플로우 | 이메일 입력 → 링크 클릭 → 로그인 |
| DB 스키마 설계 | users, visa_status, checklist_progress 등 | 마이그레이션 파일 + Gen 승인 |

**주의**: 점수 트래커에서 "자격 있다", "선발 가능성 높다" 같은 표현 금지. "현재 입력 기준 XX점" 형태로만 표시

## QA/테스트 전략

Phase별로 테스트 수준을 다르게 적용. 초기에는 빠르게, 기능 많아지면 자동화 도입.

> 📘 **E2E (End-to-End) 테스트**: 사용자 행동을 자동 시뮬레이션. "홈 접속 → 클릭 → 로그인 → 대시보드 확인" 같은 흐름을 코드로 짜놓고 매번 자동 실행.
> **Playwright**: E2E 테스트 실행 도구 (Microsoft). Chrome/Safari/Firefox에서 브라우저를 자동 조작. Claude가 코드 작성.

### Phase별 테스트 계획

| Phase | 테스트 방식 | 상세 |
|-------|-----------|------|
| **Phase 1** | 수동 테스트 | Claude가 개발 중 확인 + Gen님이 모바일 실기기 검증 + Lighthouse 체크 |
| **Phase 2** | 수동 + 브라우저 매트릭스 | Chrome(데스크톱) + Safari(iPhone) + Chrome(Android) 수동 확인 |
| **Phase 3** | 수동 + Playwright 핵심 플로우 | 로그인, 대시보드, 점수 계산 등 핵심 3~5개 플로우만 자동화 |

### 브라우저/디바이스 커버리지

| 대상 | 점유율 | 우선순위 |
|------|--------|---------|
| Chrome (데스크톱) | ~65% | 필수 |
| Safari (iPhone) | ~28% | 필수 (모바일 트래픽 61%) |
| Chrome (Android) | 포함 | 필수 |
| Firefox / Edge | ~7% | 여유 있을 때 |

### 테스트 체크포인트

매 Phase 완료 시:
- Lighthouse 모바일 ≥ 90
- Core Web Vitals "좋음" 구간 확인
- RSC 비율 ≤ 20% Client
- 디스클레이머 표시 확인 (한국 + 대만)
- Gen님 모바일 실기기 확인
